# 分级日志与可观测性设计

状态：设计稿；本次不实现代码。适用于[软件架构](architecture.md)中的本地 Node.js 服务、任务编排和远端操作模块。

## 1. 目标与边界

日志应回答：**哪个任务、哪个阶段、何时做了什么、耗时多久、结果如何、失败后能否重试**。页面和本地文件看到同一条经过脱敏的结构化记录。日志不代替任务状态：`workflow` 保存权威状态，日志提供诊断时间线。

终端按键和容器终端输出不进入应用日志。Docker 构建的 stdout/stderr 作为独立的“命令输出”流展示和限量保存；应用日志只记录构建开始、进度摘要、退出码、镜像 ID 与失败原因。这样可以查看构建细节，同时避免海量构建行淹没阶段事件。

## 2. 日志级别

阈值按 `TRACE < DEBUG < INFO < WARN < ERROR < FATAL` 排列；低于阈值的记录不写入任何持久化或实时通道。默认阈值为 `INFO`，可为当前任务临时调整到 `DEBUG` 或 `TRACE`；提高详细程度只影响之后产生的记录。

| 级别 | 使用场景 | 示例 |
| --- | --- | --- |
| `TRACE` | 高频内部细节，排查底层状态时临时启用 | 下载分块、SFTP 分块、SSH 通道状态 |
| `DEBUG` | 可重复的诊断信息，不包含凭据 | 版本匹配依据、检查命令的退出码、重试计划 |
| `INFO` | 正常阶段边界和关键结果 | 文件打包完成、远端校验通过、镜像构建成功 |
| `WARN` | 可恢复异常或需要留意的环境条件 | 下载重试、远端剩余空间接近阈值 |
| `ERROR` | 当前操作或任务阶段失败 | SHA256 不一致、Docker 权限不足、Compose 启动失败 |
| `FATAL` | 本地服务无法继续提供核心功能 | 配置无法读取、任务存储无法初始化 |

不以 `ERROR` 表示可自动恢复的单次尝试；重试过程记录 `WARN`，重试耗尽时记录一次 `ERROR`。每个阶段的成功与失败各有一条稳定的结论事件，便于页面与排障工具识别。

## 3. 记录格式与事件名

所有应用事件采用 UTF-8 JSON Lines，一行一条，字段遵循固定 schema。时间为 UTC ISO 8601；时长使用毫秒；字节数使用整数。`event` 是稳定机器名（如 `workspace.upload.verified`），`message` 是面向用户的简短中文说明。

```json
{
  "schemaVersion": 1,
  "id": "job-123:42",
  "timestamp": "2026-10-26T02:00:00.000Z",
  "level": "INFO",
  "component": "workspace",
  "event": "workspace.upload.verified",
  "message": "归档已上传并通过 SHA256 校验",
  "context": {
    "jobId": "job-123",
    "stage": "sync",
    "requestId": "req-456",
    "attempt": 1
  },
  "data": {
    "bytes": 1048576,
    "durationMs": 1240
  }
}
```

`id` 是任务内持久递增序号，供日志分页与 SSE 断线续接；服务级事件使用独立序号。失败事件另带 `error: { code, name, summary, retryable }`，其中 `code` 是稳定错误码，`summary` 不包含原始命令或凭据。只有本地 `DEBUG` 诊断模式可以保存经过脱敏的堆栈。

事件名按 `模块.动作.结果` 命名，例如 `catalog.resolve.failed`、`bundle.download.completed`、`ssh.connect.failed`、`image.preflight.failed`、`image.build.completed`、`compose.up.completed`、`terminal.session.closed`。模块新增事件前需定义级别、必要字段及敏感字段规则。

## 4. 模块职责

| 子组件 | 职责 |
| --- | --- |
| `Logger` 门面 | 提供分级记录、模块/任务/阶段子上下文、阈值过滤和稳定事件名；业务模块通过注入获得，不直接调用 `console.log` |
| `Redactor` | 在输出到任何通道前统一脱敏、截断超长字段、拒绝不能安全序列化的数据 |
| `LogStore` | 按任务追加 JSONL、分段轮转、读取分页、维护任务内序号和清理策略 |
| `LivePublisher` | 向 SSE 订阅者广播已脱敏事件，用 `id` 支持 `Last-Event-ID` 续接 |
| `ConsoleSink` | 将本地服务事件输出到控制台，便于启动失败和本机排障 |
| `CommandOutputStore` | 单独接收 Docker 构建等受控命令的 stdout/stderr，脱敏、限流、限量保存并供页面查看 |

`workflow` 创建任务上下文并记录阶段开始、完成、失败、取消和耗时；`catalog/bundle/ssh/workspace/image/compose/terminal` 记录各自的关键检查与异常；`api` 记录请求结果与 `requestId`。`web` 只消费日志，不生成服务器操作结论。`storage` 负责通用任务状态和产物，日志文件由 `observability` 模块管理。

## 5. 输出、展示与留存

- **本地文件**：任务事件写入用户数据目录的 `logs/jobs/<jobId>/events.jsonl`；服务自身事件写入 `logs/service.jsonl`。文件权限仅当前用户可读写。单段达到 10 MiB 轮转，每个任务最多保留 5 段。
- **命令输出**：按任务保存在 `build-output.log`，默认最多 20 MiB；超过容量时保留最新内容并记录一次 `observability.output.truncated` 警告。终端会话内容不保存。
- **清理**：已结束任务日志保留 14 天；总量超过 500 MiB 时先清理最旧的已结束任务。运行中的任务文件不因保留策略被删除。
- **页面**：任务时间线默认显示 `INFO` 及以上，可按级别、阶段和关键词过滤；`WARN/ERROR/FATAL` 高亮并显示可执行的下一步。构建输出在单独面板显示，避免与应用事件混排。
- **实时传输**：`GET /api/jobs/:id/logs` 支持级别、游标和分页；`GET /api/jobs/:id/events` 用 SSE 推送同一结构化记录。断线后按 `Last-Event-ID` 补发；若记录已过期，返回间断提示和当前任务状态快照。构建输出使用独立的读取/订阅接口。

进度百分比、已传字节和速率每秒最多推送一次；只有关键进度点或状态变化写入持久日志。默认 `INFO` 日志不记录每个下载块或每行 Docker 输出。

## 6. 凭据与故障处理

- 不记录 SSH 密码、私钥、口令、认证头、Cookie、访问令牌、完整含签名参数的 URL、原始环境变量、完整远端命令、终端输入。结构化字段采用允许列表；字段名含 `password`、`token`、`secret`、`privateKey` 等时再次脱敏。
- 从命令输出和异常文本中清除已知凭据值与常见 `Bearer`、URL 凭据/签名形式，随后限制单行长度。任意未标记的秘密可能混在非结构化输出中，因此构建命令应避免在 stdout/stderr 输出凭据；页面明确标识构建输出可能包含第三方程序内容。
- 脱敏发生在文件、控制台、SSE 和页面订阅之前；所有通道使用同一条已脱敏记录。日志接口仅在已授权的本地会话内开放。
- 持久化日志不可写时，服务输出简短的控制台告警，将任务标记为 `observability.degraded` 并在页面提示；原始部署错误仍保持为任务的主要错误。日志恢复后记录丢失区间，不能假装事件完整。
- 写入队列有上限并向生产者施加背压；高频 `TRACE/DEBUG` 可合并或丢弃，但需统计并记录丢弃数。`WARN` 及以上不静默丢弃，文件失败时使用控制台兜底。

## 7. 实现时的验收条件

1. 默认只记录 `INFO` 及以上；调整阈值后，过滤结果与页面一致，任务和阶段上下文可贯穿下载、上传、构建与启动。
2. 用含密码、令牌、私钥、签名 URL 的模拟输入检查文件、控制台、SSE 和命令输出，不得出现原值。
3. 模拟服务重启、SSE 断线、日志轮转与保留过期，验证游标续接或明确的间断提示。
4. 模拟构建输出洪峰与磁盘写入失败，验证任务可诊断、队列有界，日志失败不会掩盖部署失败。
5. 终端输入与终端输出不进入持久日志；构建输出单独限量保存；关键阶段事件可用于还原任务时间线。
